# AI for Product Management: 31 Claude Skills

31 Claude skills for deciding what to build, what to drop and whether it worked. For product managers, product owners and heads of product.

**Guide and download:** [meet-polar-bear.com/skills/ai-for-product-management-pack](https://meet-polar-bear.com/skills/ai-for-product-management-pack)

## What this is

The pack follows the product job from the inbox to the review after launch. It starts where the week starts, with requests you have to sort and say no to. Then it sets direction (vision, strategy, north star, OKRs, roadmap), goes out to customers (interviews, synthesis, jobs, opportunity trees, assumptions), writes the work down (PR/FAQ, prototype brief, PRD, story map, user stories), gets a decision that sticks, prepares sales, support and marketing for launch, and checks what the release actually changed. Each skill is one named method or one artifact, with the inputs it needs, where it breaks, a fixed output template, a finish line and the next skill to run.

Every skill holds one line: Real customers are not optional: Claude drafts the documents, the team talks to users, and a named person makes the call.

```
Prioritise and say no -> Set direction -> Discover -> Define -> Decide and align -> Launch -> Measure and learn
```

## Install

### In Claude Code

```
/plugin marketplace add polar-bear-org/claude-skills
/plugin install ai-for-product-management-pack@polar-bear-skills
```

### In Claude.ai

1. Turn on "Code execution and file creation" under Settings > Capabilities.
2. Go to Customize > Skills, click "+", choose "+ Create skill", then "Upload a skill", and upload the skill's zip from the `install/` folder. Repeat for each skill you want.
3. On Team and Enterprise plans, an owner first enables "Cloud code execution and file creation" and "Skills" under Organization settings > Plugins & skills (Policy tab), and can upload skills for the whole organization.

## The skills

### 1 · Prioritise and say no

| Skill | What it does | When to run it |
|---|---|---|
| [Feature Request Triage](skills/pm-feature-request-triage/SKILL.md) | Request log, why-behind-it questions, build / later / no sort, reply drafts | Sales promised it, a big client wants it, the CEO forwarded it, all this week |
| [Cost of Delay](skills/pm-cost-of-delay/SKILL.md) | Urgency profiles, CD3 order, "yes, if" options, reply to the asker | Everything is urgent and you need a no that holds |
| [RICE Prioritization](skills/pm-rice-prioritization/SKILL.md) | Scored backlog, confidence notes, out-of-order exceptions, cut list | 40 requests, room for 5, and the loudest voice keeps winning |
| [MoSCoW Prioritization](skills/pm-moscow-prioritization/SKILL.md) | Must / Should / Could / Won't list, Must budget check, Won't-this-time list | The date is fixed and scope has to give |
| [Kano Model](skills/pm-kano-model/SKILL.md) | Paired survey questions, category table per feature, build-first list | You need to know which features customers expect and which delight |

### 2 · Set direction

| Skill | What it does | When to run it |
|---|---|---|
| [Product Vision](skills/pm-product-vision/SKILL.md) | Vision statement, vision board (target group, needs, product, business goals) | The team cannot say in one sentence what it is building toward |
| [Product Strategy](skills/pm-product-strategy/SKILL.md) | Diagnosis, guiding policy, coherent actions, "we will not" list | Everything is high priority and leaders set the roadmap by preference |
| [North Star Metric](skills/pm-north-star-metric/SKILL.md) | North star, 3 to 5 named inputs with definitions, counter-metrics | The team ships a lot and cannot say which number it is moving |
| [Product OKRs](skills/pm-okrs/SKILL.md) | Quarterly objectives, measurable key results, key-result grading notes | The quarter starts and the goals are a list of features |
| [Product Roadmap](skills/pm-product-roadmap/SKILL.md) | Now-next-later board, confidence notes, what is not on it, executive version | The roadmap is yours until it is run from the CEO's inbox |

### 3 · Discover

| Skill | What it does | When to run it |
|---|---|---|
| [Customer Interview Guide](skills/pm-customer-interview-guide/SKILL.md) | Screener lines, story-based questions, probes, consent note, notes template | You have 30 minutes with a customer and cannot waste it on opinions |
| [Interview Synthesis](skills/pm-interview-synthesis/SKILL.md) | Affinity clusters, need statements with sources, contradictions, open questions | Five interview transcripts and a PRD due Friday |
| [Jobs to Be Done](skills/pm-jobs-to-be-done/SKILL.md) | Job statements, circumstances, forces for and against switching, alternatives | A request arrives with no known job behind it |
| [Opportunity Solution Tree](skills/pm-opportunity-solution-tree/SKILL.md) | Outcome, opportunity tree, target opportunity, three solution ideas, assumption tests | Discovery keeps getting squeezed and has to fit between sprints |
| [Assumption Mapping](skills/pm-assumption-mapping/SKILL.md) | Desirability, viability and feasibility assumptions, evidence map, riskiest three | The team is about to build on beliefs nobody has checked |

### 4 · Define

| Skill | What it does | When to run it |
|---|---|---|
| [Working Backwards PR/FAQ](skills/pm-pr-faq/SKILL.md) | One-page press release, customer FAQ, internal FAQ | A prototype is already built and nobody wrote down why |
| [Prototype Brief](skills/pm-prototype-brief/SKILL.md) | What it tests, pass line set in advance, what it does not prove, gap-to-production list | Leadership saw the AI demo and thinks it ships next week |
| [PRD Template](skills/pm-prd/SKILL.md) | Problem, goals, non-goals, requirements, open questions, success measures | The last spec was read five different ways |
| [Story Mapping](skills/pm-story-mapping/SKILL.md) | User activity backbone, walking skeleton, release slices | The backlog is 200 tickets and nobody can see the whole product |
| [User Stories](skills/pm-user-stories/SKILL.md) | Stories, Given / When / Then criteria, INVEST check, refinement questions | Engineers say the requirements are thin but not what is missing |

### 5 · Decide and align

| Skill | What it does | When to run it |
|---|---|---|
| [Product Role Charter](skills/pm-product-role-charter/SKILL.md) | What product owns, what others own, stop-doing list, meeting audit | You ship story points, not software, and the week is meetings and tickets |
| [DACI Decision](skills/pm-daci-decision/SKILL.md) | Driver, approver, contributors, informed, inputs, decision date | Sign-off never comes, or comes and is reversed next week |
| [Decision Log](skills/pm-decision-log/SKILL.md) | Dated records (context, decision, status, consequences), reopening rule | Settled calls keep coming back as if nobody decided |
| [Pre-Mortem Analysis](skills/pm-pre-mortem/SKILL.md) | Failure story, reasons list, top risks with owners and signals, go / adjust / stop | The launch date was promised before anyone asked what could go wrong |

### 6 · Launch

| Skill | What it does | When to run it |
|---|---|---|
| [Competitive Analysis](skills/pm-competitive-analysis/SKILL.md) | Landscape table, win / loss themes, where you differ, what not to copy | Sales keeps saying "the competitor has it" |
| [Value Proposition Canvas](skills/pm-value-proposition-canvas/SKILL.md) | Customer profile, value map, fit notes, one message all teams use | Marketing, sales and product each describe the product differently |
| [Go-to-Market Plan](skills/pm-go-to-market-plan/SKILL.md) | Launch tier, audiences, positioning line, readiness by team, enablement brief | The product is ready and sales, support and marketing are not |
| [Release Notes](skills/pm-release-notes/SKILL.md) | Customer notes by change type, internal version for support, who is affected | Support hears about changes from customers |

### 7 · Measure and learn

| Skill | What it does | When to run it |
|---|---|---|
| [Success Metrics](skills/pm-success-metrics/SKILL.md) | HEART table (goals, signals, metrics), baseline, target, guardrail | You celebrated a release and still cannot say whether it worked |
| [Experiment Design](skills/pm-experiment-design/SKILL.md) | Hypothesis, variants, primary metric, guardrails, sample check, decision rule | Two options, a strong opinion on each side, and enough users to test |
| [Post-Launch Review](skills/pm-post-launch-review/SKILL.md) | Intended versus actual, why, keep / change list, keep, fix or remove call | Two weeks after launch customers still use the old workflow |

## Example prompts

- "Run pm-feature-request-triage. Here are this week's requests from sales, support and the CEO's forward. Sort them and draft the replies."
- "Our quarter goals are a list of features. Turn them into Product OKRs with key results we can measure."
- "Here are five interview transcripts. Run pm-interview-synthesis and show me where customers contradict each other."
- "Leadership saw the prototype yesterday and wants it live next month. Write a Prototype Brief that says what it proves and what it does not."
- "The pricing page decision has been reopened three times. Set up a DACI Decision and a Decision Log entry for it."
- "We launched the new import flow two weeks ago and people still use the old one. Run a Post-Launch Review with this usage export."

## Quality bar

- **One method, applied properly.** Each skill uses the real mechanics of its method (the scales, the grid, the formula, the order of the pass), not a generic "gather, analyse, recommend".
- **It tells you where it breaks.** Every skill says when not to use it and what fits instead.
- **Same shape every time.** A fixed output template and a short "done when" check before handover.
- **No invented facts.** No made-up quotes, customers, numbers or findings. Missing data becomes a bracketed placeholder or an open question.
- **Work is scored, people are not.** Skills score requests, options, risks and assumptions, never team members or individual users. Customer data is summarised, not profiled.
- **The red line:** Real customers are not optional: Claude drafts the documents, the team talks to users, and a named person makes the call.
